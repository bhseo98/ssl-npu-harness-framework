## `mmt_block_scaled_q8` — CustomOp 실제 동작 방식

```python
@CustomOp.register(library=LIBRARY)
class mmt_block_scaled_q8(CustomOp):
    """Generic block scaled matmul with transposed RHS.
    * d:  [N, K // 32, 1]      (per-block scale)
    * qs: [N, K // 32, 32]     (int8 weight)"""
    signature = "mmt_block_scaled_q8(Tensor a, Tensor d, Tensor qs) -> (Tensor)"
```
 `CustomOp` 은 amdsharktank 게 아니라 **iree.turbine** (shark 런타임) 인프라(kernels/base.py:29 에서 `from iree.turbine.runtime.op_reg import CustomOp`). 그리고 이 클래스의 Python 은 **런타임 커널이 아니라 "컴파일 시점에 MLIR 을 만들어내는 메타코드"**

 ### 한 operation에 두조 ㅁㅇ류

 ```
mmt_block_scaled_q8 클래스
├─ signature / select  ← Python, 트레이스·컴파일 시점 실행 (shape·dtype 계산, 특수화)
├─ generate            ← Python, lowering 시점 실행 (.mlir 템플릿을 채워 emit)
└─ templates/mmt_block_scaled_q8_3d.mlir  ← 진짜 계산(마이크로커널). IREE 가 컴파일해 device 에서 돈다
```

`select`/`generate` 의 Python 은 **숫자를 계산하지 않음.** 숫자를 계산하는 건 `.mlir`
Python 은 어떤 MLIR 을 어떤 모양으로 찍어낼지만 정함

### 1. 커스텀 커널에서 Python 코드를 그대로 쓸 수 있지만 부분적으로만 가능. `select`/`generate` 안의 Python 은 그대로 쓰이지만 그건 **컴파일 시점 오케스트레이션**
device 에서 도는 커널 본체는 반드시 MLIR여야함. 임의의 Python 수식을 커널 몸통으로 넣어 NPU/GPU 에서 돌릴 수는 없음

예외 하나 — `eager_execute(*args)` (op_reg/base.py:221). 여기에 순수 Python 구현을 넣으면 **eager 모드에서만** Python 으로 돌 수 있음.
하지만 (a) AOT/export 모드에선 호출 안 되고, (b) `mmt_block_scaled_q8` 은 이걸 override 안 했다(기본 `return NotImplemented`). 그래서 이 커널은 eager 에서도 Python 이 아니라 **MLIR 을 즉석 컴파일해서** 돈다.

### 2. 나중에 커스텀할 때 어떤 Class를 바꾸려는게 뭐냐에 따라 다름. 

| 바꾸려는 것 | 손볼 곳 |
|---|---|
| 계산 알고리즘 (같은 입출력 shape) | **`.mlir` 템플릿만** (class 는 템플릿 이름·Jinja 변수만) |
| 입출력 signature·shape·specialize | `signature` + `select` + `generate` (class) |
| 어떤 모델이 이걸 쓰는지 | 디스패치 배선(`@matmul.override`) 또는 명시적 호출 |

class 는 인터페이스 + shape + 어떤 MLIR 찍을지 이고, **실제 무거운 수학적 연산은 `.mlir` 에 있다.** class 만 바꿔선 계산 내용이 안 바뀌고, class 를 안 바꾸면 op 등록·shape 추론이 없어 트레이스가 안 됨.
보통 둘 다 건드리되 비중은 `.mlir` 이 큼.

### 3. 그대로 인용되는 사례

**amdsharktank 자기 자신이 이미 그렇게 씀** ops/custom_impls.py:77-94 에서:

```python
@matmul.override(Tensor, QuantizedTensor, impl_name="amdsharktank")
def matmul_generic_tensor_block_scaled(lhs, rhs, *, transpose_rhs):
    ...
    rhs_unpacked = rhs.unpack()
    return mmt_block_scaled_q8(lhs, rhs_unpacked.d, rhs_unpacked.qs)   # ← 그대로 호출
```
모델이 `ops.matmul(x, weight)` 를 부를 때 weight 가 `BlockScaledLayout`(int8 블록 양자화)이면 **자동으로** 이 구현으로 디스패치되어 호출됨.
weight 를 그 레이아웃으로 두고, `ops.matmul`/linear 를 부르면 가능.

### 4. CustomOp는 3단계에 나눠서 만들어짐.

https://github.com/iree-org/iree-turbine/blob/main/iree/turbine/runtime/op_reg/base.py

1. **import 시점 — 정의/등록**: `@CustomOp.register(library=LIBRARY)` 실행 →
   - torch.library 에 op 정의 → `torch.ops.amdsharktank.mmt_block_scaled_q8` 생성
   - `register_meta=True` 로 **Meta impl**(트레이스용 shape 추론) 등록
   - 실제 디스패치 키(CPU/CUDA)에 **impl 트램펄린** 등록
   - 데코레이터가 **클래스를 호출 가능한 op 으로 치환** (`op_reg/base.py/return instance.op`, :138) — 그래서 `mmt_block_scaled_q8` 은 이제 클래스가 아니라 호출가능 함수
2. **호출(trace/meta) 시점 — 선택**: 매 호출마다 `select()` 실행 → 인자 shape 에서 결과 shape/dtype 산출, 특수화 결정
3. **lowering/실행 시점 — 생성**: `generate()` 가 `.mlir` 을 KernelBuilder 에 emit. eager 면 standalone 커널로 IREE JIT 컴파일·실행, AOT export 면 `util.func` 로 모듈에 splice

### 5. `.mlir` 만 바꾸면 되나? 등록하고 Python class 쓰면 되는지?

**입출력 shape/signature이 그대로면 → `.mlir` 만 바꾸면 된다.** `generate` 가 이미 "템플릿 → call_function" 배선을 해두므로, class 는 템플릿 이름·Jinja 치환값만 맞으면 됨.
다만 class 는 **반드시 있어야** 함 — op 을 torch.library 에 등록하고(없으면 `torch.ops.*` 가 안 생김), `select` 로 트레이스용 shape 를 계산하니까.

정리하면 `.mlir` = 계산 본체(여길 바꿔 새 마이크로커널), class = 등록 + shape 계약 + 어떤 템플릿 쓸지(유지/조정).

### 6. 함수 정의해놓고 호출만 하면 모델 호출이 실제로 일어남. 등록후엔 `mmt_block_scaled_q8(a, d, qs)` 처럼 평범한 함수로 부르면 된다(데코레이터가 callable op 으로 치환했으니).

- **eager(PyTorch 런타임)**: `eager_execute` 가 기본 `NotImplemented` 라서 → `generate` 가 만든 **MLIR 마이크로커널을 IREE 로 즉석 컴파일해 진짜로 실행** 계산이 실제로 돈다.
- **export(AOT)**: eager 실행 대신, 트레이스엔 op 노드로 남고 lowering 때 그 MLIR 이 모듈에 splice 됨.
- 모델 코드에선 보통 직접 안 부르고 `ops.matmul` 이 weight 타입을 보고 **자동 디스패치**로 부름(3번).

### 7. 
> Python class = **op 등록 + shape 계약 + 어떤 MLIR 을 찍을지**(컴파일 시점)
> `.mlir` = **실제 계산**(IREE 가 컴파일해 device 에서 실행). 계산만 바꾸려면 `.mlir`, 인터페이스/모양 바꾸려면 class.
> 모델에선 `ops.matmul` 자동 디스패치로 실제 호출이 일어남
> eager 든 export 든 MLIR 이 진짜로 컴파일·실행/splice 됨
